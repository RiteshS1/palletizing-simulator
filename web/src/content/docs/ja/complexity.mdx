# 計算量チートシート

n ＝ パレット上の箱の数、k ＝ 接触部分の角の数、P ＝ エクストリームポイントの数、R ＝ マルチスタートの回数、m ＝ 注文数。

| 操作 | 計算量 | 補足 |
|---|---|---|
| AABB の交差判定 | O(1) | 3つの区間の重なり |
| 1つの配置のチェック | O(n) | 配置済みの箱を1回走査し、凸包を計算 |
| 凸包（モノトーンチェーン法） | O(k log k) | 並べ替えが支配的 |
| 凸多角形の内外判定 | O(h) | すべての辺の左側にあるか |
| 重心（累積和） | 1回の問い合わせで O(1) | O(n) の再計算の代わり |
| グリーディ・レイヤー（計画全体） | O(n log n + n²) | 並べ替え＋列とルールの判定 |
| エクストリームポイント（1回の実行） | O(n · P · n) = O(n³) | P は n に比例して増える |
| エクストリームポイント（マルチスタート） | O(R · n³) | R = 12 |
| 優先度付きキューの追加／取り出し | O(log m) | 二分ヒープ |
| 届け先の参照 | 平均 O(1) | ハッシュマップ |
| BM25 検索（アシスタント） | O(チャンク数 × クエリの語数) | 転置インデックス上 |
| ウェルフォードの平均と分散 | 1サンプルにつき O(1) | 1回の走査で数値的に安定 |

## Google Benchmark による計測

`micro_bench` はホットパスを計測し、Big-O 曲線を当てはめます。

```bash
./build/release/micro_bench
# BM_CheckPlacement/64     ～マイクロ秒、O(N) に当てはまる
# BM_ExtremePoints/80      ～ミリ秒、O(N^3) に当てはまる
```

## 産業界でヒューリスティックが勝つ理由

安定性の制約付きの3次元積み付けを厳密に解くと、数分から数時間かかることがあります。セルは6〜10秒ごとに1箱を置くので、数ミリ秒で最適解の数パーセント以内に入るヒューリスティックこそが正しいエンジニアリングの選択です。
