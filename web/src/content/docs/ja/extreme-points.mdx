# エクストリームポイント

より賢いヒューリスティックは、列に縛られる代わりに、重要な場所だけを探索します。

## 考え方

箱を置いたあと、次の箱にとって有用な場所は、その箱が **作り出した角** です。右側、奥側、そして上面です。各角は **射影** もされます。他の軸に沿って壁か箱に当たるまで押し戻され、候補が積み山にぴったり寄り添うようにします。箱の内側に入ってしまった点は取り除きます。ライブモデルでは、これらの候補が青い点で、選ばれた点がオレンジで表示されます。

## 場所の選び方

各箱について、すべてのエクストリームポイント × 2つの向きを試し、積み付けのルールで無効なものを除き、残りを辞書順で比較するタプルで採点します。

1. **z が最も低い**：下から埋めて重心を低く保つ。
2. **接触面積が最も大きい**：壁や隣の箱にぴったり寄せて、隙間を減らす。
3. 最も奥、次に最も左。

「**候補を生成 → 制約で絞り込み → スコアで順位付け**」は、把持の選択から配置まで、実用的なロボットプランナーの多くが採用している型です。

## マルチスタート

計画全体を、箱の並び順を変えて12回実行し（重い順、体積順、底面積順、高さ順に加え、シード付きのランダムなノイズを加えた重い順を8通り）、最も良い結果を残します。序盤の1つの悪い判断が貪欲な実行を台無しにすることがありますが、並び順を変えるとそれを避けられることがよくあります。ノイズはシード付きなので、結果は再現可能です。

## データ構造

- 点は `std::set`（赤黒木）で保持します。挿入は O(log n)、重複は自動で除かれ、反復順序も固定です。ハッシュセットなら O(1) ですが、順序がライブラリに依存するため、プラットフォームによって同点の決め方が変わってしまう可能性があります。
- エンジンは各ステップの候補リストを出力しており、ビューアーはそれを使ってアルゴリズムの「思考」を表示しています。

## 計算量

およそ n 個の点 × 2つの向き × O(n) のルール判定を、n 個の箱それぞれで行うので、1回の実行で **O(n³)**、それを12回実行します。ネイティブで40個の箱に約 3 ms です。

## 結果

50個のシードで、箱の **90%** を配置し（グリーディ法は55%）、パレットの64%を埋め（同37%）、重心と中心のずれを 73 mm に抑えます（同 193 mm）。**50個中50個** のシードで、より多くの体積を配置しています。
