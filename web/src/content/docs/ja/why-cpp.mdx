# なぜ C++ なのか

モーションコントローラーから ROS 2 のコア、MoveIt、認識ライブラリ、プランナーまで、ものを動かすロボットソフトウェアの大半は C++ で書かれています。理由は実用的なものです。

## 予測可能な性能

- **ガベージコレクターがない** ので、制御ループの途中で予期せず止まることがありません。メモリはオブジェクトがスコープを抜けたときに決定論的に解放されます（**RAII**）。
- **ゼロコスト抽象化：** テンプレート、`std::vector`、ラムダ、クラスは、手書きと同じ機械語にコンパイルされます。
- 制御ループは 1 kHz 以上で動きます。1 ms の締め切りには、実行時のオーバーヘッドを許す余地がありません。

## エコシステム

ROS 2（`rclcpp`）、MoveIt、Eigen（線形代数）、PCL（点群）、OpenCV（画像処理）、Drake や Pinocchio（動力学）は、いずれも C++ が第一言語です。ロボットメーカーも C++ の SDK を提供しています。

## ハードウェアに近い

C++ はドライバー、共有メモリ、フィールドバスのスタック、GPU と直接やり取りでき、組み込み Linux ボードでも産業用 PC でも動きます。

## 1つのコードベース、複数のターゲット

このプロジェクトのエンジンは、同じソースからネイティブの CLI、ROS 2 ノード、ブラウザ向けの WebAssembly にコンパイルされます。これが可能なのは、コアが標準ライブラリと、移植性の高いヘッダーオンリーの依存関係だけを使っているからです。

## エンジンの一部

正確な幾何が重要です。整数ミリ、半開区間、64ビットの体積を使います。

```cpp
// 2つの箱が交差するのは、3軸すべてで区間が重なるときに限る。O(1)。
inline bool intersects(const AABB& a, const AABB& b) {
    return overlap1D(a.min.x, a.max.x, b.min.x, b.max.x) > 0 &&
           overlap1D(a.min.y, a.max.y, b.min.y, b.max.y) > 0 &&
           overlap1D(a.min.z, a.max.z, b.min.z, b.max.z) > 0;
}
```

## トレードオフ

C++ は切れ味の鋭い道具です。未定義動作（符号付き整数のオーバーフロー、範囲外アクセス）は自分の責任です。そのためこのプロジェクトでは `-Wall -Wextra -Wconversion` でビルドし、すべてのテストを **AddressSanitizer** と **UndefinedBehaviorSanitizer** の下で実行し、静的解析も使っています。メモリ安全性から Rust もロボティクスで広がりつつありますが、業界の標準は依然として C++ のエコシステムです。
