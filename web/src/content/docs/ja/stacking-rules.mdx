# 積み付けのルール

`checkPlacement()` は、すべてのアルゴリズムのために1つの問いに答えます。この配置は許されるか？ パッカーはパレット1枚につき何千回もこれを呼ぶので、チェックは軽いものから順に実行し、最初に失敗した時点で即座に返します（**フェイルファスト**）。

| 順番 | チェック | コスト |
|---|---|---|
| 1 | パレット内で最大高さ以下 | O(1) |
| 2 | 総重量が上限以下 | O(1) |
| 3 | 重なりなし・上に何もない・どれが支えているか | O(n)、1回の走査 |
| 4 | 支持率 ≥ 75% | 走査後 O(1) |
| 5 | 中心が支持多角形の内側 | O(k log k) |
| 6 | 支えているどの箱よりも重くない | O(支持する箱の数) |

## 支持率

支持面積 ＝ **上面が自分の底面と一致する** 箱との投影面の重なりの合計です（デッキ上なら底面全体）。支えている箱どうしは重なれない（重なれば衝突する）ので、単純に足し合わせて問題ありません。

## 支持多角形

物体が倒れずに立っていられるのは、**重心を真下に投影した点が、接触部分の輪郭の内側にあるとき** です。この輪郭が支持多角形で、接触領域の **凸包** にあたります。2本の柱に渡した橋は面積の50%しか支えられていませんが、中心が凸包の内側にあるので完全に安定しています。ライブモデルでは、箱が2本の柱の上を滑っていきます。青が凸包で、中心がそこから外れると箱がオレンジ色に変わります。

<Callout title="面白い事実">
長方形の中心を通る直線は、長方形を必ず2等分します。したがって底面の50%を超える部分が支えられていれば、中心は必ず凸包の内側にあります。しきい値75%では支持多角形のルールが働くことはなく、支持率を半分より下げたときに初めて意味を持ちます。
</Callout>

## 凸包：アンドリューのモノトーンチェーン法

点を x、次に y で並べ替え、左から右へ走査して下側の凸包を、右から左へ走査して上側の凸包を作ります。最後の3点が左に曲がっていなければ、真ん中の点を取り除きます。計算量は **O(k log k)** で、並べ替えが支配的です。各点は1回の走査で高々1回ずつ追加・削除されます。

曲がる向きの判定には2次元の外積を使います。

```cpp
int64_t cross(P2 o, P2 a, P2 b) {
    return (a.x - o.x) * (b.y - o.y) - (a.y - o.y) * (b.x - o.x);  // > 0: 左に曲がる
}
```

箱の中心は 0.5 mm 単位になることがあるため、コードではすべての座標を2倍にし、計算を正確な整数のまま保っています。

## 耐荷重と到達性

- **耐荷重：** 箱を自分より軽い箱の上に載せてはいけません。実際のシステムでは、「何の上に載っているか」のグラフ全体を通して荷重を合計し、各箱の圧縮強度と比べます。
- **真上から届く：** 上から降りてくるグリッパーは、たとえ空いていても張り出しの下に箱を差し込めません。物理的に成り立つことと、ロボットが実行できることは別物です。
