# アーキテクチャ

## リポジトリの構成

```text
core/          C++20 エンジン：幾何、ルール、パッカー、WES、ロボット姿勢、JSON API
  include/pal/   公開ヘッダー          src/   実装
  apps/          palletize、wes_sim、bench（CLI11）
  tests/         GoogleTest            bench/ Google Benchmark
  wasm/          ブラウザ向けの embind バインディング
ros2/          palletizer_interfaces（サービス）+ palletizer_ros（ノード、launch、テスト）
web/           Next.js サイト：ランディング、ドキュメント（MDX、英語＋日本語）、シミュレーター、AI アシスタント
docker/        ROS 2 Jazzy イメージ        scripts/  build-engine.sh、ros.sh
```

## 1つのコア、3つのフロントエンド

```text
                 ┌─▶ CLI アプリ（JSON ファイル）─▶ web/public/data
core（pal::core）─┼─▶ WebAssembly（embind）    ─▶ シミュレーターの「別の箱で試す」
                 └─▶ ROS 2 ノード              ─▶ /plan_pallet、マーカー、TF
```

3つとも `api.cpp` か同じパッカー関数を呼ぶため、コアの修正はすべてのフロントエンドに届きます。

## 座標系

- **パレット座標系：** 整数ミリ、z が上、原点はデッキの奥・左の角。積み付けはすべてここで行います。
- **ロボット基準座標系：** メートル、ROS の慣習（x が前、y が左、z が上）。配置姿勢はここで出力します。
- **three.js のシーン：** メートル、y が上。ビューアーは各パレットを、回転とスケールを与えた1つのグループで包むので、プランナーの数値をそのまま使えます。

## 主な設計判断

| 判断 | 理由 |
|---|---|
| 積み付けは整数ミリ | 「上面と底面が一致するか」を正確に比較でき、浮動小数点の許容誤差が不要 |
| Eigen は姿勢だけに使う | 回転は本質的に浮動小数点の量だから |
| 境界は JSON | ファイル、WASM、デバッグに共通のシンプルな形式 |
| シード付き・自前変換の乱数 | どのプラットフォームでも同じ結果 |
| 厳密解法ではなくヒューリスティック | 数ミリ秒で、ロボットのサイクルタイムに十分収まる |
| 静的サイト＋1つの API ルート | エンジンはブラウザで動き、サーバーが必要なのはアシスタントだけ |
