# ロボティクスを理解する

ロボットセルは小さな工場です。センサーが状況をソフトウェアに伝え、ソフトウェアが行動を決め、アクチュエーターが実行します。この **認識 → 計画 → 実行** のループが、箱1つごとに回ります。

## パレタイジングセルの構成要素

- 箱の到着を検知する光電センサー付きの **コンベヤ**。
- **ビジョン：** 3D カメラが箱のサイズと姿勢を計測し、スキャナーがバーコードを読み取ります。
- **ロボットアーム：** パレタイジングでは4軸（旋回、肩、肘、手首の回転）が一般的です。箱は正立したままなので、ツールを傾ける必要がないからです。汎用アームは6軸です。
- **エンドエフェクター：** ほとんどの箱には真空グリッパー（吸着カップと真空発生器）、重い箱や通気性のある箱にはフォーク型やクランプ型のグリッパーを使います。
- **コントローラー：** ロボットメーカーのリアルタイム制御装置と、コンベヤ・ステーション・安全を統括する PLC。

## 座標系と変換

位置には必ず基準が必要です。**座標系** とは原点と3本の軸のことです。セルには、ワールド、ロボット基準、ツール、カメラ、パレットなど多くの座標系があります。座標系どうしの変換は **剛体変換**（回転＋並進）で、4 × 4 の行列で表します。

```text
T_base_tool = T_base_pallet · T_pallet_tool
```

右から左に読みます。パレット座標系で分かっている姿勢を、ロボットに対するパレットの位置を通してつなげると、ロボットが必要とする姿勢が得られます。PalletLab の `robot_cell.cpp` は、Eigen の `Isometry3d` でまさにこれを行っています。このページのライブモデルには `world`、`robot_base`、`pallet`、`tool` の各座標系が表示され、ツール座標系が各箱の配置姿勢へ移動していく様子を確認できます。

## 運動学

- **順運動学（FK）：** 関節角度 → ツールの位置。関節ごとの変換を掛け合わせるだけなので簡単です。
- **逆運動学（IK）：** 目標のツール姿勢 → 関節角度。こちらは難しく、解が複数ある（肘が上か下か）ことも、届かない姿勢なら解がないこともあります。4軸パレタイザーは閉形式の簡単な IK を持ち、6軸アームは解析的なソルバーや数値最適化を使います。

## 回転とクォータニオン

回転は、行列、オイラー角、**クォータニオン**（`x, y, z, w`）で表せます。クォータニオンはジンバルロックを避け、滑らかに補間できるため、ROS や多くのロボット API で使われています。回転は常に **単位** クォータニオンであり、私たちのテストでも確認しています。

## ピック＆プレースのサイクル

1. コンベヤ上の箱を検出し、計測する。
2. パレット上の置き場所を計画する（このプロジェクトの役割）。
3. ピック位置の上へ移動して降下し、真空をオンにして把持を確認する（真空圧センサー）。
4. 置き場所の上の **アプローチ姿勢** へ移動し、**配置姿勢** まで鉛直に降下する。
5. 離して上昇し、繰り返す。良いセルはこれを6〜10秒で行います。

<InterviewJa>
**「その姿勢はどの座標系か？」** は、ロボティクスで最もよくあるバグの原因です。変数名に座標系を含め（`T_base_pallet`）、単位をそろえましょう（ROS はメートルとラジアンを使います）。
</InterviewJa>
